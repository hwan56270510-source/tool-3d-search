# labeling: 박스 → SAM 마스크 → YOLO-Seg 라벨 (수동 라벨링 도구)

사진에서 공구에 마우스로 박스만 그리면 SAM 2.1이 정확한 윤곽(마스크)을 잡아 주고, YOLO-Seg 형식 라벨(polygon)로 저장한다.
이 라벨 하나로 YOLO(1클래스 `tool`)와 CNN(drill / hammer / clamp / other)을 모두 학습한다.

```text
data_prep (yolo/images) ─ [labeling] ─ make_session_splits ─┬─ YOLO-Seg 학습 (1클래스)
                                                              └─ CNN 학습 (종류 분류)
```

## 준비
- 환경: Python 3.10 이상, `pip install ultralytics opencv-python numpy`
  - `opencv-python-headless`는 창을 띄우지 못하므로 쓰면 안 된다.
- **모니터 앞에서** 실행한다. 원격(SSH)으로는 창이 뜨지 않는다.
- GPU가 있으면 빠르다. 없어도 CPU로 돌아가지만, 박스마다 1~2초씩 걸린다.
- SAM 가중치(`sam2.1_b.pt`, 약 160MB)는 처음 실행할 때 자동으로 받는다.
  이미 받아 둔 파일이 있으면 `labeling/weights/sam2.1_b.pt`에 두거나 `--sam <경로>`로 지정한다.

## 실행
```bash
python labeling/label_box_sam.py \
  --images <데이터>/yolo/images \
  --list labeling/lists/label_list.txt \
  --out <데이터>/det/labels \
  --names drill,hammer,clamp
```

| 옵션 | 설명 |
|---|---|
| `--images` | 라벨링할 사진 폴더 (`data_prep`에서 만든 `yolo/images`) |
| `--list` | 라벨링할 파일 이름 목록. 한 줄에 하나씩 쓴다. 생략하면 폴더 전체를 라벨링한다. |
| `--out` | 라벨 저장 폴더. **같은 폴더로 다시 실행하면 라벨이 없는 사진부터 이어서 한다.** |
| `--names` | 클래스 이름 (쉼표 구분). **순서가 곧 클래스 번호**이므로 팀 전체가 `drill,hammer,clamp`로 통일한다. |
| `--auto` | 자동 제안 켜기 (아래 설명). 실행 중 `a` 키로도 켤 수 있다. |
| `--display_width` | 화면 표시 폭(px, 기본 1500). 모니터가 작으면 줄인다. 라벨은 원본 크기 기준으로 저장된다. |
| `--start_from_first` | 이어하기 대신 첫 사진부터 시작한다. 이미 만든 라벨을 검수할 때 쓴다. |

## 조작
| 키 | 동작 |
|---|---|
| 왼쪽 드래그 | 박스 그리기 → SAM 마스크 생성. 한 사진에 여러 개 그릴 수 있다. |
| `0` / `1` / `2` | 현재 클래스 선택 (`--names` 순서: drill / hammer / clamp). **박스를 그리기 전에** 고른다. |
| `Space` / `Enter` / `n` | 저장하고 다음 사진 |
| `e` | **"물체 없음"**으로 저장하고 다음 사진 (배경 사진, 빈 라벨 파일) |
| `b` | 저장하고 이전 사진 |
| `u` | 마지막 박스 취소 |
| `r` | 이 사진의 박스 전부 지우기 |
| `a` | 자동 제안 켜기/끄기 |
| `q` / `Esc` | 저장하고 종료 |

### 자동 제안 (`--auto` 또는 `a`)
직전 사진의 박스를 조금 넓혀서 다음 사진에 SAM 마스크를 미리 잡아 준다. 제안은 하늘색으로 "auto"라고 표시된다.
- 맞으면 `Space`로 저장하고 넘어간다.
- 틀리면 `u` 또는 `r`로 지우고 다시 그린다.

연속된 사진에서 물체가 크게 움직이지 않을 때 빠르다. 크기가 직전 박스의 1/4~4배를 벗어나는 제안은 자동으로 버린다.

## 라벨링 규칙 (팀 공통)
1. 공구 전체가 들어가게 박스를 그린다. 가려진 부분은 보이는 곳까지만 그린다.
2. 공구가 없는 사진도 일부는 반드시 `e`로 "물체 없음"을 저장한다. YOLO의 오검출을 줄이고, CNN의 `other` 클래스 재료가 된다.
3. 마스크가 이상하게 잡히면(배경까지 번짐 등) `u`로 지우고 박스를 조금 다르게 다시 그린다.
4. 저장된 미리보기(`--out/previews/`)를 가끔 열어서 마스크가 공구에 맞는지 확인한다.
5. 애매한 물체(비슷한 색의 부품 등)는 혼자 정하지 말고 팀에서 정한 클래스 정의를 따른다.

## 출력 (`--out` 아래)
| 경로 | 내용 |
|---|---|
| `labels/<사진이름>.txt` | YOLO-Seg 라벨 `cls x1 y1 x2 y2 ...` (0~1 정규화 polygon). 물체 없음이면 빈 파일. **학습에 쓰는 파일** |
| `ann/<사진이름>.json` | 박스 원본. 다시 열면 이 박스로 마스크를 다시 만들어서 수정할 수 있다. |
| `masks/<사진이름>.png` | 마스크 (확인용) |
| `previews/<사진이름>.jpg` | 오버레이 미리보기 (확인용) |

`labels/` 라벨의 클래스 번호는 `--names` 순서(drill=0, hammer=1, clamp=2)를 그대로 쓴다.
YOLO용 1클래스 변환(전부 0)과 train/val/test 분할은 다음 단계(`make_session_splits.py`)에서 한다.

## 라벨링할 사진 고르기 (`lists/`)
연속된 사진(0.5초 간격)은 거의 같아서, 전부 라벨링하는 것보다 **골고루 띄엄띄엄** 고르는 게 효과적이다.
classroom_v4에서 실제로 쓴 목록:

| 파일 | 사진 수 | 고른 방법 |
|---|---|---|
| `lists/label_list.txt` | 140 | 약 5장마다 1장 |
| `lists/label_list_add1.txt` | 135 | 1차 라벨 사이 중간 사진 (drill 52, hammer 33, clamp 30) + 배경 20장 |

두 목록을 같은 `--out`으로 차례로 실행하면 classroom_v4 라벨 275장이 된다.
